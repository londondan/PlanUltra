# PRD-003: Visual Design System — Ridge Light
**Status:** Approved
**Created:** 2026-03-16
**Direction chosen:** Concept B — Ridge Light
**Reference mockup:** `requirements/mockups/concept-b-ridge-light.html`
**Deliverables:** Style guide (this document) + UX refactor work items (Section 8)

---

## 1. Summary

PlanUltra adopts the **Ridge Light** design system: clean white and Mist content surfaces, Midnight navy as the primary text color (replacing generic black), Ridge Blue as the single interactive accent, and the Blue Ridge mountain silhouette as a hero element on the landing and sign-in pages. The result is a modern SaaS aesthetic with a distinct sense of place — immediately recognisable, never generic.

This document is the canonical style guide. All future UI development must reference it. When a component or pattern is not covered here, the developer should derive the answer from the principles in Section 2 and document the decision here.

---

## 2. Design Principles

**Depth through color, not shadow.** Shadows are minimal and cool-tinted (never warm gray). Depth is expressed using the palette — Midnight anchors text, Ridge Blue signals interaction, Mist provides surface warmth.

**Navy, not black.** The primary text color is `#02071E` (Midnight). It reads as near-black but carries the blue mountain identity into every line of body text. Generic `#000000` or `#111111` is never used.

**One accent color.** Ridge Blue (`#1D7CBE`) is the only interactive accent. Buttons, links, active tabs, input focus rings, and left-border card accents all use it. There are no secondary accent colors competing for attention.

**Mountains at the edges.** The mountain silhouette SVG belongs on the hero/landing and sign-in pages — the atmospheric moments of the experience. Inside the authenticated app, the palette does the work quietly. The actual mountain imagery is not used as a repeated background texture on every screen.

**Whitespace is structure.** Content areas are white or near-white. Section separation uses subtle `#DBF1FA` (Mist) washes or `#82C7F6` (Sky) borders — never heavy ruled lines or colored bands inside the app shell.

## 4. Typography

### Font stack

Two fonts. No more.

**Display / headings: DM Sans** (`next/font/google` — `DM_Sans`)
Geometric, high x-height, slightly condensed at heavy weights. Purpose-built for display sizes — reads as fast and purposeful without being casual. Weights: `700`, `800`.

```ts
import { DM_Sans } from 'next/font/google'
const dmSans = DM_Sans({
  subsets: ['latin'],
  weight: ['700', '800'],
  variable: '--font-display',
})
```

**UI / body: Geist Sans** (unchanged — already loaded)
Optimized for interface density. Good tabular figures for data tables, legible at 12–14px. Used for all chrome: nav, labels, inputs, table cells, metadata, badges, body copy.

**Mono: Geist Mono** (unchanged)
Arrival times, distances, any numeric readout that needs optical alignment.

### Usage rule

| Context | Font |
|---|---|
| Hero title, page h1, race name, section h2, card title, logo wordmark | DM Sans |
| Nav links, labels, body copy, table cells, badges, metadata, inputs, buttons | Geist Sans |
| Arrival times, distance values, pace inputs | Geist Mono |

Never mix display and UI fonts within the same text block. If an element is below 16px, use Geist Sans regardless.

### CSS custom property

```css
/* Add to globals.css @theme inline block */

```

Set `--font-dm-sans` on `<html>` via the Next.js font `variable` prop (same pattern as the existing Geist setup in `layout.tsx`).

## 9. Decisions Log

| Decision | Choice | Rationale |
|---|---|---|
| Design direction | Concept B — Ridge Light | Clean and modern, highest content density readability, Midnight text gives brand identity without heavy dark-mode complexity |
| Dark mode | Deferred — remove existing dark block | Concept B is a light-mode-first design; dark mode requires its own palette derivation and is out of scope for this refactor |
| Mountain imagery | SVG polygon silhouette on landing/sign-in only | Keeps authenticated app clean; mountain SVG is lightweight, no asset dependency |
| Map tiles | Standard outdoor/terrain tiles (Leaflet/Mapbox default) | Complements light surfaces; dark tiles reserved for Concept A which was not chosen |

## 10. Amendment — Card Contrast, Hover, and Table Striping
**Added:** 2026-03-16
**Triggered by:** Visual QA on Plan tab section cards and aid station/drop bag summary tables

### Problems identified

Three issues were found during review that the original PRD-003 spec described correctly in prose but did not translate into precise enough implementation guidance for the shadcn base components:

**Issue 1 — Cards are invisible against the page background.**
The shadcn `Card` component ships with `ring-1 ring-foreground/10` — a single pixel ring at 10% foreground opacity. On a white page with Midnight foreground, that renders as a ~18% gray hairline border. Combined with `bg-card` = white, the card and the page background are effectively the same color. There is no visual separation.

**Issue 2 — Card hover does nothing.**
The shadcn `Card` component has no hover styles. The PRD-003 §5 spec described a Mist fill + Ridge Blue left border on hover, but this was never implemented in `card.tsx`.

**Issue 3 — Tables have no row striping.**
The shadcn `TableRow` component uses `hover:bg-muted/50` for hover but applies no alternating background. Every body row renders white-on-white. PRD-003 §5 specified odd rows in Mist, even rows in white, but `table.tsx` does not implement this.

---

### Updated spec: Card component

Replace the current `ring-1 ring-foreground/10` approach with an explicit border and shadow. This is the authoritative replacement for the "Card (default)" spec in Section 5.

```
Card (default):
  background:     white (bg-card)
  border:         1px solid rgba(130, 199, 246, 0.6)   ← Sky at 60% — visibly separates from white page
  border-left:    3px solid transparent                ← reserved for hover accent
  border-radius:  0.75rem (rounded-xl)
  box-shadow:     0 2px 6px rgba(29, 124, 190, 0.07)  ← subtle cool shadow
  transition:     border-color 0.2s, background-color 0.2s, box-shadow 0.2s

Card hover (clickable cards — add group/hover only on interactive cards):
  background:     Mist #DBF1FA
  border-color:   Sky #82C7F6
  border-left:    3px solid Ridge Blue #1D7CBE
  box-shadow:     0 4px 16px rgba(29, 124, 190, 0.12)
  transform:      translateY(-2px)
```

The `SectionCard` in the Plan tab is not a navigation card and should not lift on hover. Apply the border/shadow improvements but omit `translateY` and the Ridge Blue left border for non-clickable cards.

**Two card variants to implement:**

| Variant | When to use | Hover behavior |
|---|---|---|
| `interactive` | Dashboard race cards, any card that navigates or opens something | Full hover: Mist fill + Ridge Blue left border + lift |
| `static` | Section cards, info panels, non-clickable containers | Border + shadow only — no fill change, no lift |

The header `<tr>` inside `<thead>` will also pick up `odd:bg-muted` since it's the first `<tr>` in the table. Prevent this by scoping the stripe to `tbody` only:

```diff
- "border-b transition-colors odd:bg-muted even:bg-white hover:bg-[rgba(130,199,246,0.30)] ..."
```

Apply the stripe classes to `TableBody`'s children only. Two options:

**Option A** — scope via `TableBody` (preferred): add `[&_tr]:odd:bg-muted [&_tr]:even:bg-white` to `TableBody` instead of `TableRow`, and remove them from `TableRow`.

**Option B** — scope via CSS: apply `tbody tr:nth-child(odd) { background: var(--muted); }` in `globals.css`.
